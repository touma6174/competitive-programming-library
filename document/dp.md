## 1. DPの基本構造と解法の思考プロセス

### DPを適用するための前提条件
1. **部分構造最適性 (Optimal Substructure)**: 全体の最適解が、部分問題の最適解から構成できること。
2. **重複する部分問題 (Overlapping Subproblems)**: 同じ部分問題が何度も繰り返し現れること。

### 思考の4ステップ
1. **状態（`dp` 配列）を定義する**: 「何を添字にすれば過去の履歴を必要十分かつコンパクトに表せるか」を決める。
2. **遷移式（Recurrence Relation）を立てる**: `dp[i]` を求めるために、どの前の状態（`dp[i-1]` など）が必要かを立式する。
3. **初期条件と境界条件を設定する**: 基準となる `dp[0]` などの値を設定する。
4. **計算順序を定める**: 遷移元が必ず計算済みになる順番（通常はループを小さい順・トポロジカルソート順）でループを回す。

## 2. 基礎・超頻出の定番DP

| 名称 | 概要・状態定義の例 | 計算量 | 主な特徴・用途 |
|---|---|---|---|
| **ナップサックDP** | `dp[i][j]` = $i$ 番目まで見て重み和が $j$ のときの最大価値 | $O(NW)$ | 定番中の定番。個数制限の有無で遷移が変化 |
| **LCS (最長共通部分列)** | `dp[i][j]` = 文字列 $S$ の $i$ 文字目、 $T$ の $j$ 文字目までのLCS長 | $O(\|S\|\|T\|)$ | 2つの系列を一致させる問題に応用可能 |
| **LIS (最長増加部分列)** | `dp[i]` = 長さ $i$ の増加部分列における最小の末尾の値 | $O(N \log N)$ | 二分探索（`std::lower_bound`）で高速化するのが定石 |
| **区間DP** | `dp[l][r]` = 区間 $[l, r)$ に対する最適解 | $O(N^3)$ | 隣接要素の結合・削除（例: 石さらいゲームなど） |

## 3. 応用・発展の典型DPパターン

### 1. bitDP（集合DP）
- **状態定義**: `dp[S][v]` = 訪問済み頂点の集合が $S$（bit表現）で、現在頂点 $v$ にいる状態の最適解。
- **用途**: ナップサックに入らないほど小さい制約（$N \le 20$ 程度）での全探索代替。巡回セールスマン問題 (TSP) など。
- **計算量**: $O(2^N \cdot N^2)$ または $O(2^N \cdot N)$。

### 2. 桁DP (Digit DP)
- **状態定義**: `dp[i][is_less][...]` = 上から $i$ 桁目まで決めて、上限 $N$ より確実に小さいか（`is_less`）フラグを持った状態数。
- **用途**: 「$N$ 以下の整数のうち、条件を満たすものの個数」を求める問題。
- **計算量**: $O(\text{桁数} \times \text{条件の状態数} \times 10)$。

### 3. 確率DP・期待値DP
- **確率DP**: スタートから順方向に確率を遷移させる（`dp[i]` = 状態 $i$ になる確率）。
- **期待値DP**: ゴールから**逆方向**にたどって定義することが多い（`dp[i]` = 状態 $i$ からゴールするまでの期待値）。

## 4. DPの高速化テクニック

| テクニック | 対象となる遷移式の形 | 高速化後の計算量 | 主な道具・特徴 |
|---|---|---|---|
| **累積和高速化** | $dp[i][j] = \sum_{k=l}^{r} dp[i-1][k]$ | $O(N^2) \to O(N)$ | 区間和を前計算で $O(1)$ 化 |
| **データ構造高速化** | $dp[i][j] = \max_{k} (dp[i-1][k])$ | $O(N^2) \to O(N \log N)$ | セグメント木や BIT (`fenwicktree`) を利用 |
| **CHT (Convex Hull Trick)** | $dp[i] = \min_{j} (a_j \cdot x_i + b_j)$ | $O(N^2) \to O(N \log N)$ / $O(N)$ | 直線群の下側凸包を保持（Li Chao Tree など） |
| **インライン化 (次元削減)** | $dp[i][j]$ が $dp[i-1][...]$ にしか依存しない | メモリ削減 $O(NW) \to O(W)$ | 1次元配列を後ろから更新して使い回す |

## 5. DPとグラフ・木構造の融合

### 1. 木DP (Tree DP)
- **特徴**: 木の葉から根に向かって DFS で状態を帰還させながら計算します。
- **計算量**: 通常 $O(N)$。部分木サイズを合わせた「二乗の木DP（Tree Knapsack）」は一見 $O(N^3)$ に見えて $O(N^2)$ に収まる有名な評価があります。

### 2. 全方位木DP (Rerooting)
- **特徴**: すべての頂点を根とした場合の木DPの答えを一括で求めます。
- **アルゴリズム**:
  1. 任意の頂点を仮の根として普通の木DPを行う (DFS1回目)。
  2. 親方向からの結果も合わせて全方位に伝播させる (DFS2回目)。
- **計算量**: $O(N)$（適切なモノイド演算の宣言が必要）。

## 6. 実戦でのバグ回避・デバッグのコツ

1. **配列の初期化**:
   - 最小化問題（`chmin`）なら `INF` (十分大きな値)、最大化問題（`chmax`）なら `-INF` または `-1` で全要素を初期化する。
   - オーバーフローに注意（`INF + val` で `long long` を超えないように `1e18` などを使用）。
2. **`chmax` / `chmin` テンプレート関数の利用**:

   ```cpp
   template<class T> inline bool chmax(T& a, T b) { if (a < b) { a = b; return 1; } return 0; }
   template<class T> inline bool chmin(T& a, T b) { if (a > b) { a = b; return 1; } return 0; }
   ```
